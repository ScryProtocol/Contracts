Overview

One surface for check, claim, and resolve.

The API is already live. It reserves available labels under hey.eth, exposes claimed records from the directory, and signs CCIP responses for offchain resolution. The only missing piece for normal ENS wallets is the mainnet resolver switch.

01

Discover

Start with GET /heyeth/docs so an agent can discover the live route set without a browser flow.

02

Sign

Ask POST /heyeth/auth/challenge for the exact wallet-signing message tied to a handle and owner address.

03

Claim

Submit the signed nonce to POST /heyeth/claim to create or update the label.hey.eth directory record.

Endpoints

The route set is small, explicit, and terminal-ready.

These are the routes an agent actually needs. No page state, no UI session, no embedded app logic.

DISCOVERY

GET /heyeth/docs

Returns docs JSON with branded endpoint URLs, example request bodies, zone status, and pay hub metadata.

LOOKUP

GET /heyeth/handle/:handle

Checks whether a label is claimed and returns the current owner, marker, address map, and pay hub reference.

QUERY

GET /heyeth/handle?label=...

Supports query-style lookup too, so agents can call a stable path and pass the label as a query param.

DIRECTORY

GET /heyeth/info/:handle

Returns the claimed handle record directly, including the owner and published addresses.

UPDATE

PUT /heyeth/handle/:handle

Updates a claimed handle with a fresh signed nonce from the same owner wallet. This is the explicit later-edit route.

AUTH

POST /heyeth/auth/challenge

Returns the exact EIP-191 message to sign for a handle and owner wallet before a claim or update.

CLAIM

POST /heyeth/claim

Reserves an available label and writes default ETH and BAL records for the supplied owner address. Same-owner updates still work here for backward compatibility, but PUT /heyeth/handle/:handle is the cleaner edit path.

CCIP

POST /heyeth/ccip

Serves signed gateway responses for resolver calls like addr() under *.hey.eth.

STATUS

GET /heyeth/status

Reports the current hey.eth owner, resolver, and whether the resolver already supports extended resolution.

Examples

Start in your terminal with simple HTTP.

No frontend session, just requests.

The goal is fast automation. Discover the route set, check a label, request a signing challenge, submit the signed claim, and hit the CCIP gateway without ever touching browser UI.

claim.sh
# request a signed claim challenge curl -sS https://statechannel.org/heyeth/auth/challenge \ -H 'content-type: application/json' \ --data '{ "handle": "agent007", "owner": "0x1234567890123456789012345678901234567890" }' # sign the returned challenge.message with the owner wallet, then claim curl -sS https://statechannel.org/heyeth/claim \ -H 'content-type: application/json' \ --data '{ "handle": "agent007", "owner": "0x1234567890123456789012345678901234567890", "nonce": "from-auth-challenge", "signature": "0x...", "addresses": { "ETH": "0x1234567890123456789012345678901234567890", "BTC": "bc1qexample..." } }'
update.sh
# later edits use PUT on the claimed handle curl -sS -X PUT https://statechannel.org/heyeth/handle/agent007 \ -H 'content-type: application/json' \ --data '{ "owner": "0x1234567890123456789012345678901234567890", "nonce": "from-auth-challenge", "signature": "0x...", "addresses": { "BTC": "bc1qupdated..." } }'
lookup.sh
# inspect a label curl -sS https://statechannel.org/heyeth/handle/agent007 # or query the stable handle endpoint curl -sS 'https://statechannel.org/heyeth/handle?label=agent007' # inspect live resolver status curl -sS https://statechannel.org/heyeth/status # inspect Sepolia pay.eth metadata curl -sS https://statechannel.org/heyeth/pay/sepolia
ccip.sh
# send a CCIP gateway request curl -sS https://statechannel.org/heyeth/ccip \ -H 'content-type: application/json' \ --data '{ "sender": "0xResolverAddress", "data": "0x..." }'
Current Status

The API is live; ENS wallet resolution is now onchain-enabled.

Signed claims and CCIP responses are live through statechannel.org/heyeth/*, and hey.eth now points at an offchain-capable resolver on Ethereum mainnet. Standard ENS clients can resolve supported *.hey.eth records through the gateway.

Current public references: GET /heyeth/status and GET /heyeth/pay/sepolia
